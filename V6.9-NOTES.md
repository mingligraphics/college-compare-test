# V6.9 test-site access reliability

Scope: only mingligraphics/college-compare-test. Based on V6.8 (580978a). No production site, mini-program or database writes.

The previous directory and extended detail/comparison separately required cross-origin Supabase POST requests, with no full static fallback. Network failures, timeouts or rejection of an otherwise valid directory by strict schema validation left the catalog empty. AbortSignal.timeout and Object.hasOwn also introduced compatibility risks in older embedded browsers. These are plausible explanations for the reported failure, not a verified diagnosis of the user's mainland connection.

The directory, complete public detail rows and pair comparisons now use a single same-origin JSON snapshot first. All 301 IDs and every directory field must match the corresponding detail. Missing detail fields or inconsistent schema fail validation. Existing public display modules retain verified policy overrides, citations and intentional missing-data labels. There is no invented completion of missing school facts. Program filters still use the existing same-origin program index. Online APIs are a bounded fallback only if the static snapshot fails. Both failures show a retry button and failure text, with no misleading 0/0 count. Selected-pair session cache is no longer read. AbortController plus a cleared timer replaces AbortSignal.timeout.

## Repeatable data updates

1. Run `python3 scripts/export-static.py` with network access. It only POSTs read requests to the two existing public endpoints. No database writes or credentials are needed.
2. The exporter checks 301 unique IDs, every requested pair, all directory/detail values, a fixed 57-field public detail allowlist and nested public program/source fields. Unknown fields stop export for review. Do not add private audit files or raw database exports.
3. It writes `data/schools-<sha256-prefix>.json` and `snapshot-config.js`. Keep previously published snapshot files so old open pages can still obtain their release's data. No manually maintained second school dataset.
4. Run `node scripts/build.mjs`, validate, and commit only test-site files. The build recreates dist with public assets and stamps script/style/program-index URLs with content versions in the Pages root and dist. Snapshot filenames change with content; runtime memory belongs to the current page, and obsolete session detail caches are ignored. No service worker is added.
5. Push the test repository's main branch; its existing Pages source is main, root. Verify the resulting Pages run and served release files.

Current export: 816,582 bytes UTF-8; 112,683 bytes with local gzip (approximately 113 KB). Pages negotiates its own transfer encoding, so this is a compression estimate, not a promise of a particular client transfer size. The snapshot includes all 301 complete 57-field public detail rows plus directory rows. It exactly matches the existing public snapshot captured for V6.7; no data facts were changed.

Remaining external acceptance: real mainland Wi-Fi/mobile networks and actual WeChat/iPhone Safari must be checked by the user's sister or colleague. Desktop Chromium mobile viewport/compatibility simulations do not constitute mainland or real-device testing.

## Validation before publication

Build and JavaScript/inline-script syntax checks passed. Chromium regression passed nine combinations: API blocked at 320/390/430/1440px, delayed resource loading, normal availability, static request failure with online fallback, both requests failing followed by successful retry, and missing AbortSignal.timeout/Object.hasOwn with stale pair session cache. Search, region/budget/program filters, three sort choices, detail/compare, share URL and direct detail/compare routes passed; all 301 static detail rows were compared exactly with the exported public rows. No browser page errors were observed. Mobile screenshots were inspected. These are Chromium simulations, not real Safari/WeChat devices.
